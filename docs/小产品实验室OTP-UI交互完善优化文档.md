# 小产品实验室 OTP｜UI 与交互完善优化文档

**版本：** 1.0（待确认）  
**日期：** 2026-08-25  
**范围：** 围绕验证码、密码、迁移与备份完善界面、导航、状态反馈与操作连贯性；移除不服务核心路径的辅助模块，不改变本地优先的安全边界。

## 一、优化目标

本轮不再以“功能数量”作为价值来源，而是让用户在已经存在的能力中更快完成四件最重要的事：**查看并复制验证码、添加验证码、导出加密备份、从微信恢复备份**。密码账本、生成器、二维码转换、WebDAV、回收站和设置均继续保留，但不应遮挡 OTP 主流程。

> 产品应当让用户感觉“打开就能用、关键操作不迷路、敏感动作有清楚反馈”，而不是让用户学习一套复杂的安全系统。

| 体验原则 | 落地方式 |
|---|---|
| **OTP 优先** | 首页始终以验证码列表、搜索、复制、添加为视觉主角。 |
| **本地安全可感知** | 在需要时解释“数据在本地、导出前加密”，不在每个页面重复安全教育。 |
| **备份路径短** | 微信导出与导入使用明确、相互对应的两个入口，降低换机焦虑。 |
| **状态可预期** | 加载、保存、复制、导出、导入、失败和完成都给出统一的即时反馈。 |
| **不打断用户** | 非主流程功能留在“实用工具”或“数据管理”，不占用首页核心区域。 |

## 二、现有模块与核心路径

当前工程已有 OTP 首页、验证码录入、密码账本、密码生成器、二维码转换、数据管理、WebDAV、微信导入导出、回收站、设置等页面。本次仅保留和完善这些核心路径。

| 用户目标 | 当前涉及页面 | 建议优化重点 |
|---|---|---|
| 获取验证码 | OTP 首页 | 让“点击复制”区域更明确，复制后反馈更短、更确定。 |
| 新增验证码 | 首页新增菜单、扫码、手动录入 | 让“扫码添加”和“手动添加”成为一眼可分辨的两个选择；录入页保留实时预览与保存状态。 |
| 找回或换机 | 数据管理、微信导入导出、设置备份口令 | 将微信导入导出提升为数据管理中的首要入口；首次使用需要口令时，提供可返回的连续路径。 |
| 云端留存 | WebDAV 配置、云端备份与恢复 | 配置、测试连接和备份列表的状态关联清楚，不让用户猜“是否已配置”。 |
| 其他安全工具 | 密码账本、生成器、二维码、可疑检查 | 均保留在工具层，不抢占 OTP 首页的注意力。 |

## 三、页面级 UI 与交互优化方案

### 3.1 OTP 首页：让复制和添加成为最短路径

OTP 首页应只承担“看验证码、复制验证码、找验证码、添加验证码”四件事。现有验证码卡片的发行商、账号、验证码、倒计时和进度信息完整，后续优化以层级和反馈为主，不改变字段和功能。

| 优化项 | 当前体验风险 | 调整方案 | 验收标准 |
|---|---|---|---|
| 验证码可点击性 | 用户可能不知道应点击验证码区域复制。 | 使验证码区域与“点击复制”形成更明显的整体点击面；在复制后用轻量 Toast 显示“验证码已复制”。 | 任意验证码可在一次点击内复制，反馈不遮挡下一次操作。 |
| 添加入口 | 扫码与手动录入若混在同一菜单中，首次用户需要判断。 | 在新增菜单中明确呈现“扫码添加”和“手动添加”，配短说明，不增加新入口。 | 用户在两秒内能区分“扫二维码”和“自己填密钥”。 |
| 搜索与筛选 | 搜索、排序和筛选同时出现时容易产生视觉噪声。 | 搜索默认收起；激活搜索后再显示排序入口；清空操作始终可见。 | 搜索结束后能一键回到完整验证码列表。 |
| 空状态 | 首次用户不知道下一步。 | 空状态只给两个主按钮：扫码添加、手动添加；不堆叠安全建议或教程。 | 首次打开不需要阅读长文即可进入录入。 |
| 安全状态信息 | 安全提示过大时会抢占验证码列表。 | 保留现有提示能力，但降为轻量状态行或折叠入口，不阻塞验证码查看。 | 用户仍能看到提示，但验证码列表保持在首屏主视觉。 |

### 3.2 验证码录入：降低不确定性，保留实时预览

现有录入页已具备发行商、账号、Base32 密钥、位数、周期、算法和实时预览。优化不新增字段，而是减少解释的分散感。

| 优化项 | 调整方案 | 验收标准 |
|---|---|---|
| 录入顺序 | “发行商—账号—密钥”保持为第一屏连续流程；高级参数继续默认收起在下方。 | 用户完成常见 6 位、30 秒、SHA1 账号时不用触碰高级选项。 |
| 密钥说明 | 将“可带空格或连字符”等说明紧贴密钥输入框；预览错误直接对应输入状态。 | 填错密钥时用户知道需要修正什么，而不是只看到保存失败。 |
| 保存反馈 | 保存按钮在不可用时明确显示不可用状态；成功后返回列表并保留刚添加条目可见。 | 新增后用户能立即确认验证码已出现。 |

### 3.3 数据管理：首页入口按“换机优先级”重新排布

数据管理当前包含 WebDAV 配置、云端备份与恢复、微信导入导出和回收站。模块保留不变，但入口应按换机与恢复的频率和理解成本排序。

| 建议顺序 | 模块 | 入口文案与状态 |
|---:|---|---|
| 1 | 微信导入导出 | **微信备份与恢复**；副文案“导出加密文件，换机后从微信导入”。 |
| 2 | 云端备份与恢复 | **WebDAV 云端备份**；未配置时显示“未配置”，已配置时显示最近一次备份时间。 |
| 3 | WebDAV 配置 | **云端备份设置**；副文案“坚果云地址、账号与应用密码”。 |
| 4 | 回收站 | **回收站**；副文案保留条目数量与保留期限。 |

该调整只是调整视觉排序、文案与状态呈现，点击后仍进入原有页面和逻辑。

### 3.4 首次数据后的备份密码引导：先体验，再保护

首次打开小程序不弹出密码要求。用户可以浏览、扫码和填写录入表单；只有成功保存第一条 OTP 或密码账本条目后，才显示一次“建议建立备份密码”的提示。提示提供“去设置”和“稍后”两个选择：前者直接定位至设置页的备份密码区域，后者不影响刚保存的数据，且本次会话不重复打扰。设置页继续允许用户在二次确认后使用空密码，但必须明确说明空密码会降低备份保护。

| 场景 | 页面反馈 | 目的 |
|---|---|---|
| 新用户首次打开 | 无提示 | 不制造试用门槛。 |
| 首次成功保存 OTP / 密码 | 一次轻量提示，可跳转设置 | 在数据已有价值时提示保护。 |
| 用户暂不设置 | 不回滚保存、不反复弹窗 | 保留用户控制权。 |
| 从微信导出或恢复 | 未设置时直接定位设置页，并保留待执行操作 | 把密码设置融入必要流程。 |

### 3.5 微信导入导出：做成一对清楚、连续的动作

微信导入导出是本轮最需要打磨的现有能力。用户只需要理解：**导出会生成加密文件并发送到微信；换机后从微信选择同一个文件，再输入相同口令恢复。**

| 场景 | 交互完善方案 | 不改变的安全逻辑 |
|---|---|---|
| 首次导出 | 用户未设置备份口令时，先显示“设置口令后即可继续导出”的说明；跳转设置后返回原页面，并保留待执行的导出意图。 | 口令仍只本地保存；不允许无口令导出。 |
| 导出执行中 | 使用现有加密进度遮罩，文案明确为“正在加密备份文件”；完成后提示“已生成加密文件，请在微信中选择发送对象”。 | 文件仍先在小程序沙箱中生成，再调用微信文件转发。 |
| 导出完成 | 成功反馈不要只写“已发送”，而应解释下一步：“建议发送给自己或保存到微信收藏，换机后从本页导入”。 | 不读取微信聊天内容，不保存用户选择的聊天对象。 |
| 导入文件 | 选择文件前先说明“请选择此前导出的 `.bak` 文件”；读取后先校验格式。 | 只允许用户主动选择单个文件，不扫描文件夹。 |
| 导入完成 | 在写入前展示“将合并数据，不覆盖较新的本地记录”；完成后显示新增/更新数量，并提供“查看验证码”返回动作。 | 仍使用较新记录优先的合并逻辑。 |
| 错误处理 | 口令错误、文件格式错误、用户取消、读取失败分别给出不同且可行动的提示。 | 不在错误提示中泄露文件内容或口令。 |

### 3.6 WebDAV：从“配置表单”变为可理解的备份状态

WebDAV 不需要增加能力，但配置页、测试连接和云端列表应让用户理解当前状态。

| 状态 | 建议显示 | 下一步操作 |
|---|---|---|
| 未配置 | “尚未配置云端备份” | 主按钮“开始配置”。 |
| 配置未验证 | “已填写，尚未测试连接” | 主按钮“测试连接”。 |
| 连接成功、无备份 | “连接正常，尚未创建云端备份” | 主按钮“立即备份”。 |
| 已有备份 | 显示最近备份时间、数量和恢复入口 | 提供“立即备份”与“恢复”操作。 |
| 连接失败 | 说明是地址、账号、应用密码或网络问题，并保留表单内容 | 主按钮“重新测试”。 |

### 3.7 视觉与反馈统一规则

本轮只统一现有视觉语言，不引入新的品牌体系或复杂动效。

| 交互状态 | 统一表现 |
|---|---|
| 可点击操作 | 主操作使用稳定的蓝色按钮/卡片，次操作使用描边样式。 |
| 不可操作 | 保留按钮位置但降低对比度，并给出原因，例如“请先填写密钥”。 |
| 执行中 | 统一使用加载遮罩或按钮加载态；避免重复点击。 |
| 成功 | 轻量 Toast 用于复制、保存等短动作；导入导出等关键结果使用说明性弹窗。 |
| 失败 | 先说明发生了什么，再给出唯一的下一步，不使用泛化的“未知错误”。 |
| 危险操作 | 删除、清空等继续使用明确的红色确认和不可逆说明。 |

## 四、实施优先级

| 优先级 | 工作项 | 涉及页面 | 预期价值 |
|---|---|---|---|
| **P0** | OTP 首页复制、添加、搜索与空状态的层级和反馈统一 | 首页、验证码编辑页 | 提高每日使用效率。 |
| **P0** | 微信导出/导入的首次口令、执行中、成功、失败和恢复完成路径 | 数据管理、设置页 | 降低换机、误操作和备份理解成本。 |
| **P1** | 数据管理入口排序及 WebDAV 状态卡 | 数据管理、WebDAV 页面 | 让用户知道该先做什么。 |
| **P1** | 密码账本、生成器、二维码转换与可疑检查的工具页样式和反馈对齐 | 实用工具及相关页面 | 保留功能，但减少认知负担。 |
| **P2** | 全局空状态、按钮禁用态、加载态、错误文案复核 | 全部现有页面 | 提升整体一致性。 |

## 五、明确不做的内容

本轮不会新增 AI、云服务、账号体系、社交分享能力、后台任务、文件夹选择、自动备份、额外安全扫描模块或新的数据类型。也不会删除现有页面、改变本地加密机制、改变 TOTP 计算规则，或把密码、验证码密钥、备份口令发送到网络。

## 六、验收流程

实施后应在微信开发者工具和真机分别走完以下路径：

| 编号 | 验收路径 | 通过条件 |
|---:|---|---|
| 1 | 打开首页 → 复制验证码 → 搜索 → 清除搜索 | 每一步有明确可见的状态反馈，且不离开首页。 |
| 2 | 首页 → 新增 → 扫码添加 / 手动添加 → 保存 | 两种添加方式清楚；有效数据保存后立即出现在列表。 |
| 3 | 数据管理 → 微信备份与恢复 → 导出至微信 | 未设口令时能完成设置并回到导出；加密进度和导出成功文案清晰。 |
| 4 | 新设备/模拟数据 → 数据管理 → 从微信导入 | 能选择 `.bak` 文件；口令、格式和合并结果均有不同提示。 |
| 5 | 数据管理 → WebDAV 云端备份 | 配置、测试、备份、恢复状态可理解且可返回。 |
| 6 | 各工具页 | 主按钮、禁用态、加载态、成功和失败反馈符合统一规则。 |
